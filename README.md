# 마피아 (오프라인 모임용 웹앱)

둥글게 앉아서 하는 오프라인 마피아를, 각자 휴대폰 웹으로 진행하는 앱.
한 명이 방을 만들면 QR 이 뜨고, 나머지는 그 QR 을 찍어 입장한다.
나레이션은 각자 한쪽 이어폰으로 개인별 재생된다.

## 실행

```bash
npm install
npm run dev
```

http://localhost:3000 접속. 종료는 Ctrl+C.

## 테스트

기본 흐름(방 생성 → QR → 자리 → 밤 → 투표 → 종료) 한 판을 자동으로 돌린다:

```bash
npm test
```

특수 직업 시나리오 테스트는 직업 배정을 고정해야 하므로 **테스트 훅을 켠 서버**가 필요하다.
PowerShell 에서 별도 터미널에 이렇게 띄운다:

```bash
$env:MAFIA_TEST_HOOKS='1'; $env:PORT='3100'; node server/index.js
```

그런 다음:

```bash
$env:URL='http://localhost:3100'; node test/roles.mjs
```

`MAFIA_TEST_HOOKS=1` 일 때만 `deterministicRoles` 설정이 열리고, 직업이 편성표 순서대로
자리 번호에 배정된다(자리 1번 = roles[0]). 운영 서버에서는 이 스위치가 아예 막혀 있다.

## 봇으로 돌려보기

사람을 모으지 않고도 게임을 굴려볼 수 있다. 봇은 **사람과 똑같이 서버가 내려주는
개인화 상태만 보고** 판단하므로, 봇이 할 수 있는 행동은 사람도 할 수 있는 행동이다.
판단 로직은 `server/bot-brain.js` 한 곳에 있고, 방 안의 봇과 터미널 봇이 이걸 함께 쓴다.

### 화면에서 봇 넣기 (혼자 테스트할 때)

**터미널 없이 브라우저/폰만으로 된다.** 방을 만들면 대기실에 봇 버튼이 나온다.

1. 방을 만든다
2. `🤖 봇 +1` / `+3` / `+7` 으로 인원을 채운다 (직업 편성은 자동으로 맞춰진다)
3. 자리 정하기로 넘어가 **내 자리를 먼저 고른다** — 봇은 사람이 앉을 때까지 기다렸다가
   남은 자리를 채운다
4. 게임 시작

이후 봇이 알아서 밤 능력을 쓰고 투표한다.
각 봇 옆의 `빼기` 버튼이나 `−1` 로 인원을 줄일 수 있고, 대기실에서만 추가·제거가 된다.

**진행 설정의 「자동 진행」을 켜면 방장이 버튼을 누르지 않아도 단계가 알아서 넘어간다.**
혼자 테스트할 때 이걸 켜두면 토론 시간도 20초로 줄어서 한 판이 금방 끝난다.
자동 진행을 꺼두더라도 **방장이 죽거나 접속이 끊기면 자동으로 넘어간다** —
죽은 사람이 계속 버튼을 눌러줘야 방이 굴러가는 일은 없다.

### 직업 하나씩 체험하기

대기실의 **🧪 직업 체험** 카드에서 직업을 하나 누르면 **게임 시작 때 그 직업을 받는다.**
편성표에 그 직업이 없으면 자동으로 끼워 넣고, 삼둥이처럼 3종 세트가 필요한 직업은
나머지 둘도 같이 넣는다.

- 한 번 해본 직업에는 ✓ 가 붙고 `n / 20 해봄` 으로 진행도가 보인다 (이 기기에만 저장)
- 인원이 모자라 못 쓰는 직업(삼둥이 8인+)은 회색으로 잠긴다
- 정신병자처럼 진짜 직업이 나중에 밝혀지는 경우는 게임이 끝날 때 진짜 직업으로 기록된다

봇 7명 채우고 → 직업 하나 찜하고 → 시작 → 끝나면 대기실로 돌아와 다음 직업.
이 흐름으로 20종을 전부 눌러볼 수 있다.

### 터미널에서 한 판 보기

```bash
npm run bots -- 8
```

8명 전원 봇으로 한 판을 끝까지 돌리고, 각자의 실제 직업과 밤·투표 행동을 전부 출력한다.
관전자 시점이라 누가 무슨 짓을 했는지 다 보이므로 규칙 확인에 제일 쓸모 있다.

```bash
npm run bots -- 8 --roles random     # 특수 직업이 섞인 무작위 편성
npm run bots -- 10 --roles '["mafia","mafia","police","guardian","detective","clown","jindo","citizen","citizen","citizen"]'
```

### 봇 사이에 사람으로 끼기

```bash
npm run bots -- 8 --humans 1
```

봇이 방을 만들고 **터미널에 QR 을 그려준다.** 브라우저로 들어가 남은 자리에 앉으면
나머지는 봇이 알아서 진행한다. 실제 UI 를 직접 만져보며 확인할 때 쓴다.
`--hold 초` 로 각 단계에서 화면을 붙잡는 시간을 조절한다 (사람이 있으면 기본 12초).

> localhost 주소는 같은 PC 의 브라우저에서만 열린다. 폰으로 붙으려면 `PUBLIC_URL` 을
> 지정해 배포한 뒤 그 주소로 접속해야 한다.

### 여러 판 돌려 밸런스 보기

```bash
npm run sim -- --games 60 --players 8
```

무작위 편성으로 N판을 연속으로 돌리고 진영별·직업별 승률, 평균 진행 일수,
그리고 **진행이 멈추거나 예외가 난 조합**을 정리해 준다. 실패한 판은 편성표와
그 시점의 전원 직업·생존 상태를 같이 찍어주므로 재현하기 쉽다.

```bash
npm run sim -- --games 100 --players 10 --roles auto     # 기본 편성만
npm run sim -- --games 120 --parallel 6 \
  --roles '["mafia","mafia","police","guardian","detective","citizen","attention","clown"]'
```

| 옵션 | 설명 |
|---|---|
| `--games N` | 판 수 (기본 20) |
| `--players N` | 인원 (기본 8) |
| `--roles` | `random`(기본) · `auto` · JSON 배열로 편성 고정 |
| `--parallel N` | 동시에 굴릴 판 수 (기본 4). 판수가 많을 때 실행 시간을 크게 줄인다 |
| `--config` | 규칙 A/B 비교용 설정 주입. 예: `--config '{"strictNeutralElimination":false}'` |

> **측정할 때 주의.** 무작위 편성은 편성 자체가 결과의 가장 큰 변수라서 판마다 편차가 크다.
> 실제로 동일 설정을 60판씩 두 번 돌렸을 때 마피아 승률이 63% 와 78% 로 갈렸다.
> 규칙 변경의 효과를 보려면 **편성을 JSON 으로 고정하고 100판 이상** 돌려서 비교해야 한다.

### 인원수별 밸런스 찾기

```bash
node test/balance.mjs --games 60 --parallel 20
```

`(인원, 마피아 수, 중립 수)` 조합을 하나씩 대입해 돌리고, 인원수별로 가장 균형에
가까운 조합을 뽑아준다. 편성표를 직접 비교하고 싶을 때는:

```bash
node test/balance.mjs --games 60 --sets "저격+부정=sniper,rigger,jindo,police,guardian,detective,soldier,gymrat;회장+무소속=chairman,independent_mafia,jindo,police,guardian,detective,soldier,gymrat"
```

봇의 판단 기준은 `test/bot.mjs` 에 모여 있다. 마피아는 아군을 죽이지 않고,
드러난 마피아가 있으면 시민이 그쪽을 노리는 정도의 최소한만 넣었다.
승률을 진지하게 보려면 이 부분을 먼저 손봐야 한다.

### 그 밖의 보조 스크립트

```bash
node test/fill-room.mjs ABCD 4
```

브라우저 플레이어에게 특정 직업을 쥐여주고 싶으면 (테스트 훅 서버 필요):

```bash
node test/ui-driver.mjs '["citizen","citizen","citizen","police","sniper","chairman"]'
```

봇이 방장이 되어 방을 만들고, 마지막 자리를 사람 몫으로 비워둔다. 위 예시에서는
브라우저 플레이어가 6번 자리에 앉으면 회장을 받는다.

## 배포 (Render)

1. 이 폴더를 GitHub 저장소로 올린다.
2. Render 에서 New → Blueprint 로 `render.yaml` 을 읽힌다.
3. 배포가 끝나면 발급된 주소를 환경변수 `PUBLIC_URL` 에 넣고 재배포한다.
   **이걸 안 하면 QR 이 localhost 를 가리켜서 다른 폰에서 입장이 안 된다.**

무료 플랜은 15분 유휴 시 잠들기 때문에, 모임 시작 몇 분 전에 한 번 접속해서 깨워두는 게 좋다.

## 구조

```
server/
  index.js      Express + Socket.IO. 방 저장소, 이벤트 라우팅, 페이즈 타이머, 방 안 봇 구동
  bot-brain.js  봇의 판단 로직 (개인화 상태만 입력으로 받는다)
  game.js       Room 클래스. 자리/인접 계산, 밤 해결, 투표 해결, 승패 판정, 개인화 상태 뷰
  roles.js      직업 레지스트리 (전체 직업 정의 + 밤 행동 메타데이터)
  narration.js  나레이션 대사 사전
public/
  index.html / app.js / style.css   모바일 웹 클라이언트
  narration.js                      음성 재생기 (mp3 우선, 없으면 브라우저 TTS)
  audio/                            녹음한 나레이션을 넣는 곳
test/
  smoke.mjs     5인 게임 전 구간 자동 검증 (30개 항목)
  roles.mjs     특수 직업 15개 시나리오 검증 (61개 항목)
  bot.mjs       터미널에서 방에 붙는 봇 (판단은 server/bot-brain.js 사용)
  balance.mjs   인원수·편성 조합을 대입해 승률을 재는 밸런스 스윕
  compose.mjs   무작위 직업 편성 생성기
  play.mjs      봇으로 한 판 돌리기 (사람 참가 가능)
  simulate.mjs  여러 판 연속 실행 + 승률/안정성 리포트
  fill-room.mjs 이미 만든 방에 더미 플레이어 붙이기
  ui-driver.mjs 브라우저 플레이어에게 원하는 직업을 쥐여주는 드라이버
```

상태는 전부 서버 메모리에 있다. 서버가 재시작되면 진행 중인 방은 사라진다.
플레이어는 `playerId` 를 localStorage 에 저장하므로, 폰 화면이 꺼지거나 앱을
잠깐 나갔다 와도 자동으로 원래 자리로 복귀한다.

### 개인화 상태

서버는 모든 플레이어에게 같은 상태를 보내지 않는다. `Room.viewFor(playerId)` 가
그 사람이 알아도 되는 것만 골라서 내려보낸다. 남의 직업, 남의 밤 행동, 남의
개인 정보는 애초에 그 폰으로 전송되지 않으므로 개발자 도구를 열어도 볼 수 없다.

## 나레이션 음성 넣기

AI Studio 의 Gemini TTS 로 **한 명령에 전부 생성**할 수 있다.

```bash
$env:GEMINI_API_KEY='발급받은키'; npm run narration
```

34개를 만들어 `public/audio/` 에 넣고 `manifest.json` 까지 갱신한다.
대본과 연출 지시는 `tools/narration-script.mjs` 에 있고, 마음에 안 드는 대사는
거기서 고친 뒤 `npm run narration -- --only <키>` 로 그것만 다시 만들면 된다.

손으로 넣고 싶으면 `public/audio/` 에 파일을 두고 `manifest.json` 에 키를 추가하면 된다.
등록하지 않은 키는 자동으로 브라우저 TTS 로 대체되므로 **한 번에 다 만들 필요 없다.**
자세한 내용은 `public/audio/README.md` 참고.

## 직업 추가하기

1. `server/roles.js` 에 항목을 추가하고 `implemented: true` 로 둔다.
2. 밤 능력이면 `night: { order, targets, prompt, narrationKey }` 를 채운다.
   `order` 는 해결 순서 — 차단(10) → 보호(20) → 포섭(35) → 살해(40) → 목격(50) → 정보(60).
   투표 중에 쓰는 능력이면 `day: { kind, once, prompt }`, 게임 시작 시 1회면 `start` 를 쓴다.
3. 표준 패턴(지목/보호/살해)으로 표현되지 않는 효과는 `game.js` 의 `resolveNight()`
   해당 단계에 분기를 추가한다. 낮 능력은 `snipe()` / `forceVote()` 를 참고.
4. 개인 승리 조건이 있으면 조건이 성립하는 곳에서 `this.soloWins.push(...)` 하고,
   진영 승리를 막아야 하는 중립이면 `blocksTeamWin` 을 켠다.
5. 투표로 죽지 않아야 하면 `voteImmune: true` 하나면 된다. 사망 처리는 전부
   `applyDeaths()` 한 곳을 지나므로 면역·연쇄·순서 규칙이 자동으로 적용된다.

새 직업을 넣었으면 `test/roles.mjs` 에 시나리오를 하나 추가하는 걸 권한다.
직업 간 상호작용은 눈으로 검토해서는 거의 잡히지 않는다.

## 구현 범위

**돌아가는 것**

- 방 생성 / QR 입장 / 코드 입장 / 끊겨도 자동 재접속
- 인원수에 맞춘 직업 편성 (자동 편성 버튼 포함) + 편성 유효성 검사
- 원형 자리 지정 (마피아의 「양옆」 판정 기준)
- 밤 → 아침 → 토론 → 투표 → 처형 루프, 시간 초과 시 자동 진행
- 개인별 나레이션 큐 (마피아에게만 마피아 안내가 들림)
- 승패 판정(진영 승리 + 개인 단독 승리 + 진돗개 편승), 종료 시 전원 직업 공개, 재시작

**직업 20종 전부 구현됨**

| 진영 | 직업 |
|---|---|
| 마피아 | 마피아 · 저격수 · 부정선거자 · 회장 · 무소속당(마피아) · 삼둥이(마피아) |
| 시민 | 시민 · 경찰 · 수호자 · 탐정 · 헬창 · 군인 · 정치인 · 기자 · 무소속당(시민) · 정신병자 · 삼둥이(시민) |
| 중립 | 진돗개 · 관종 · 연쇄살인마 · 삐에로 · 삼둥이(셋째) |

「포섭된 마피아」는 회장의 능력으로만 생기며 로비에서 직접 편성할 수 없다.

**능력 발동 시점**

| 시점 | 직업 |
|---|---|
| 게임 시작 | 진돗개(각인) |
| 밤 | 마피아 계열 · 경찰 · 수호자 · 탐정 · 헬창 · 군인 · 기자 · 연쇄살인마 · 삐에로 · 삼둥이 셋째 |
| 투표 중 | 저격수 · 정치인 |

밤 행동 해결 순서는 **차단(헬창) → 보호(수호자) → 포섭(회장) → 살해 → 목격(경찰) → 정보(탐정·기자·셋째)** 다.

## 규칙을 정하고 넘어간 부분

스펙에 명시되지 않아 판단해서 구현한 것들이다. 다르게 하고 싶으면 알려주면 바꾼다.

### 공통

1. **「양옆」의 기준** — 죽은 사람은 원에서 빠지고, 그 다음 생존자가 옆사람이 된다.
   로비 설정에서 물리 자리 고정(옆이 죽었으면 그쪽으로는 못 죽임)으로 바꿀 수 있다.
2. **동표** — 아무도 처형하지 않는다. 로비 설정에서 변경 가능.
3. **마피아 여러 명** — 진영 전체가 밤에 **한 명만** 죽인다. 각자 자기 양옆을 지목하고,
   가장 많이 지목된 사람이 대상이 된다(동수면 그중 무작위). 마피아는 밤에 동료의 지목을
   실시간으로 볼 수 있어 말하지 않고도 한 명으로 몰아줄 수 있다.
   로비 설정에서 「각자 독립적으로 죽임」으로 되돌릴 수 있다.
   지목에 참여한 마피아는 대상이 자기 지목이 아니었더라도 **살해를 시도한 것으로 취급**되어
   경찰에게 목격될 수 있다.
4. **마피아끼리 서로를 안다** — 게임 시작 시점부터 서로의 직업이 보인다. 포섭된 마피아도 포함.
5. **사망자의 직업** — 밤 사망·처형 모두 공개하지 않는다. (기자의 특종만 예외)
6. **경찰의 목격 판정** — 지목한 사람이 그날 밤 살해를 *시도*했으면 목격으로 친다.
   수호자에게 막혀 실제로는 안 죽었어도 목격된다. 회장의 포섭과 삐에로의 가짜 총성은 살해가 아니다.
7. **탐정** — 진짜 직업 1개와 가짜 직업 1개를 섞어서 보여준다. 가짜는 **이번 판 편성표 안에서만**
   뽑는다. (편성표는 공개 정보라, 없는 직업이 후보로 뜨면 정답이 바로 드러난다)
8. **능력 소모 시점** — 1회성·충전식 능력은 지목한 순간 소모된다. 헬창에게 막혀도 소모된 것으로 본다.
9. **개표** — 죽은 사람이 던진 표, 그리고 개표 전에 죽은 사람(저격 등)에게 간 표는 모두 무효다.
   남은 유효표로 처형 대상을 정한다.
10. **제한 일수** — 20일(`maxDays`)을 넘기면 **마피아가 시간 안에 이기지 못한 것으로 보고
    시민 진영이 승리**한다(`maxDaysWinner: 'CITIZEN'`). 서로 죽일 수단이 없는 생존자만 남으면
    (예: 삐에로 1명 + 정치인 1명) 규칙상 영원히 끝나지 않는 상황이 실제로 나오는데,
    이를 무승부로 흘려보내는 대신 마피아 쪽에 시간 압박으로 돌린 것이다.
    로비에서 끄면 예전처럼 무승부가 된다. 살아 있는 시민이 하나도 없을 때는
    시민의 승리라고 부를 수 없으므로 이 경우만 무승부로 남는다.

### 승리 판정

10. **우선순위** — 개인 단독 승리(관종·삐에로·삼둥이 셋째)가 즉발로 먼저 성립하고,
    그 다음에 진영 승리를 본다. 동시에 성립하면 공동 승리로 처리한다.
11. **중립과 진영 승리** — 스펙대로 중립이 살아 있으면 시민도 마피아도 이기지 못한다.
    마피아 과반 조건도 마찬가지로 막힌다. 단, 진돗개는 **주인 진영의 승리는 막지 않고 같이 승리**한다.
    로비의 `strictNeutralElimination` 을 끄면 연쇄살인마만 진영 승리를 막도록 완화할 수 있다.
    (완화하는 쪽이 시민에게 유리할 거라 보고 측정했으나 결과는 반대였다 — 아래 밸런스 절 참고)
12. **관종** — 강제 지정(정치인)은 표가 아니므로 승리 조건에 포함되지 않는다.
    실제 득표가 생존자 과반을 넘어야 한다.

### 직업별

13. **삼둥이 사망 순서** — 순번이 뒤인 형제가 살아 있으면 사망이 무효화된다(수호자 보호와 동일).
    투표로 지목되어 살아남으면 그 사실만 공개되고 이유는 밝히지 않는다.
14. **삼둥이가 서로를 아는 범위** — 첫째와 둘째는 서로를 「삼둥이」로 알아보되 순번은 모른다.
    셋째는 아무도 모르고, 아무도 셋째를 모른다. 셋째의 승리 조건이 성립하려면 이래야 한다.
15. **삼둥이 셋째의 정답** — 두 형제가 **누구인지**만 맞히면 된다. 첫째·둘째 순번까지 구분할 필요는 없다.
16. **저격수 판정** — **실제 직업** 기준이다. 정신병자는 「정신병자」로 맞혀야 하고,
    삼둥이 3종은 「삼둥이」 하나로 합쳐서 판정한다. 고를 수 있는 직업은 이번 판 편성표 안에서만이다.
17. **회장의 포섭** — 마피아 공통 능력의 변형이므로 **양옆 제한을 그대로 따른다.**
    포섭한 밤에는 살해가 일어나지 않고, 수호자의 보호로도 막히지 않는다.
    포섭된 사람은 즉시 통보받고 기존 직업을 완전히 잃는다.
18. **정신병자** — 능력 있는 시민 직업 중 이번 판에 없는 것 하나를 뒤집어쓴다.
    UI 상 지목은 정상적으로 되지만 아무 효과가 없다. 기자에게 폭로되면 본인도 진짜 직업을 알게 된다.
19. **진돗개** — 직업 확인 단계에서 주인을 정한다. 방장이 강제로 넘기면 무작위로 각인된다.
20. **삐에로** — 가짜 총성을 낸 **그날 밤 다음 투표**에서 실제로 누가 처형되어야 1점이다.

## 밸런스 측정 결과

봇의 투표 판단이 단순(사실상 무작위)하므로 절대 수치보다는 **바꾸기 전후의 차이**를 보는
용도다. 실제 사람은 토론으로 마피아를 좁혀가므로 시민 승률은 아래보다 높게 나온다.

### 봇으로 잴 수 있는 것과 없는 것

**시민 승률은 봇으로 측정할 수 없다.** 시민이 이기려면 토론으로 마피아를 찾아내야 하는데
봇은 추리를 하지 못하기 때문이다. 실제로 봇의 투표 방식을 바꿔봤더니 이렇게 갈렸다
(8인 · 마피아 2 · 같은 편성, 각 80판):

| 봇 투표 방식 | 마피아 승률 |
|---|---|
| 각자 무작위로 찍음 (표가 갈려 처형이 잘 안 일어남) | 59% |
| 한 명으로 의견을 모음 (매일 처형되지만 대상은 무작위) | 80% |

규칙은 하나도 안 바꿨는데 21%p 가 움직인다. 무작위로 처형하면 8명 중 6명이 시민이라
시민이 더 많이 죽기 때문이다. 즉 **아래 수치들은 「시민이 전혀 추리하지 못할 때」의
하한선**이고, 사람이 하면 시민 승률은 이보다 훨씬 높다.

봇으로 믿고 쓸 수 있는 것은 다음과 같다.

- 진행이 멈추거나 예외가 나는 조합 찾기 (안정성)
- 평균 게임 길이 — 시민이 정보를 모을 시간이 얼마나 있는지
- 규칙 변경의 **방향** (마피아가 세지는지 약해지는지)

### 측정 방법에 대한 경고

처음에는 무작위 편성 60판으로 쟀는데, **동일 설정을 두 번 돌렸더니 마피아 승률이
63% 와 78% 로 갈렸다.** 편성 자체가 결과의 가장 큰 변수라 60판으로는 15%p 차이도
판별할 수 없다. 그래서 아래 수치는 전부 **편성을 고정하고 120판씩** 돌린 것이다
(표준오차 약 4.5%p). 규칙을 비교할 때는 반드시 이렇게 해야 한다.

기준 편성: `마피아 ×2 · 경찰 · 수호자 · 탐정 · 시민 · 관종 · 삐에로` (8인)

### 규칙별 비교 (각 120판)

| 설정 | 마피아 | 시민 | 개인 승리 | 무승부 | 평균 일수 |
|---|---|---|---|---|---|
| **현재 기본값** | 48% | 24% | 16% | 12% | 6.1일 |
| 공유 킬 끄기 (각자 독립 킬) | 59% | 23% | 7% | 9% | 4.6일 |
| 중립 완화 (`strictNeutralElimination: false`) | 64% | 29% | 7% | 0% | 3.0일 |

**마피아 공유 킬**은 마피아 승률을 59% → 48% 로 내린다. 다만 표준오차를 감안하면
1.7σ 수준이라 확정적이지는 않다. 이 편성은 마피아가 2명뿐이라 효과가 작게 나오고,
마피아가 3명 이상인 편성에서는 차이가 더 커질 것으로 본다.

**중립 완화는 의도와 반대로 작동했다.** 시민을 도우려던 변경인데 마피아가 +16%p,
시민은 +5%p 에 그쳤고 중립 개인 승리가 16% → 7% 로 반토막 났다.
살아 있는 중립이 마피아의 과반 승리를 막아주던 브레이크가 사라지면서 게임이
6.1일 → 3.0일 로 짧아진 탓이다. 짧아진 만큼 시민이 추리할 시간도, 삐에로가 3점을
채울 시간도 없어졌다. 그래서 기본값은 스펙 그대로 두었다.

### 기본 편성만 (8인 × 40판, 특수 직업·중립 없음)

| 항목 | 값 |
|---|---|
| 마피아 진영 승리 | 57% |
| 시민 진영 승리 | 43% |

중립과 특수 직업을 뺀 코어 루프는 거의 반반이다.

## 아직 안 한 것

- 중립끼리의 승리 우선순위 세부 조정 (여러 중립이 동시에 조건을 채우면 전원 공동 승리로 처리 중)
- 밤 행동에 개별 제한시간을 두는 UI (현재는 밤 전체에 하나의 타이머)
- 관전자(사망자) 전용 채팅이나 정보 화면
